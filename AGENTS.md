# iOS native rebuild gotcha (SDK 57 precompiled modules)

If a fresh `npx expo run:ios` build crashes at launch with `Symbol not found` /
`Termination Reason: Namespace DYLD` referencing an Expo module (e.g.
`ExpoFileSystem` expecting a symbol from `ExpoModulesCore`), it's an ABI skew
between SDK 57's precompiled Expo module binaries — not your code.

Fix: in `ios/Podfile.properties.json` (gitignored, regenerated by
`expo prebuild`) add `"EXPO_USE_PRECOMPILED_MODULES": "false"`, then
`rm -rf ios/Pods ios/Podfile.lock && cd ios && pod install`, then rebuild.
This forces all Expo modules to compile from source in one pass instead of
linking mismatched precompiled xcframeworks.

This must be re-applied every time `expo prebuild` regenerates `ios/` (it
resets `Podfile.properties.json` to defaults) — check for this crash first
if a rebuild after adding a new native module fails the same way.
